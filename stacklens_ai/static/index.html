How StackLens Works in Production

A rigorous, offline-first workflow designed for AI cluster operators and ML engineers:

01 / CAPTURE

Offline Rust Probes

The standalone stacklens binary collects host sysfs, /proc, drivers, and CUDA toolkits into versioned Schema-v1 JSON.

stacklens snapshot > host.json
02 / COMPARE

Forensic Snapshot Diffing

Structurally compare a known-working node against a broken node to highlight driver drifts and missing runtime libraries.

stacklens diff left.json right.json
03 / INFER

Authoritative Rules

Evaluate driver branches against authoritative CUDA family matrices (11.x ≥ 450, 12.x ≥ 525, 13.x ≥ 580) with zero LLM hallucinations.

python -m stacklens_ai.preflight
04 / EXPLAIN

NVIDIA Nemotron on Nebius

Send sanitized findings to nemotron-3-super-120b-a12b on Nebius Token Factory for grounded explanation and safe follow-up steps.

python -m stacklens_ai.preflight --smoke-test

About StackLens AI Architecture

Separation of Observation, Inference, and Recommendation:

  • Observation: The Rust CLI inspects local hardware, sysfs nodes, NVIDIA driver interfaces, and CUDA paths. It emits deterministic Schema-v1 JSON with zero external network access.
  • Inference: The deterministic diagnostic engine evaluates four core rules against authoritative NVIDIA tables, detecting driver deficiencies, selector collisions, and kernel-userspace version desynchronization.
  • Recommendation: When enabled, NVIDIA Nemotron on Nebius Token Factory receives curated, path-free fact packages. Explanations must match verified finding IDs, and verification commands are restricted to a fixed allowlist.
